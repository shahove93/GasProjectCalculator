# Архитектура расширения ГСВ

Статус: этап ГСВ принят; этап Windows installer утверждён пользователем 2026-11-11.

## Существующее приложение

- `app/calculator.py` — функции расчёта ГСН.
- `app/main.py` — FastAPI, Pydantic, `GET /`, `POST /calculate`.
- `frontend/index.html` — единая HTML/CSS/JavaScript форма.
- `tests/` — unittest, API-проверки через TestClient.

## Предлагаемое расширение

1. Оставить текущие функции ГСН и `POST /calculate` совместимыми с baseline.
2. Вынести расчёт ГСВ в отдельный `app/gsv_calculator.py` без зависимости от HTTP
   и интерфейса. Параметры: тип заказчика, длина, диаметр, количество отверстий,
   количество комплектов САКЗ, ПК, район; тарифы и ограничения — в VISION.
3. Добавить отдельные Pydantic-модели запроса/ответа и `POST /calculate/gsv`.
   Возвращать базу, доплату за длину, бурение, САКЗ, ПК, район, подытог,
   НДС и итог. В новых расчётах использовать точную денежную арифметику.
4. В существующей форме добавить выбор ГСН/ГСВ/ГСН + ГСВ и соответствующие поля.
   Результат должен явно показывать тип расчёта; смена режима не должна
   оставлять прежнюю сумму как результат новых параметров.
5. Добавить `POST /calculate/combined`: общие тип заказчика и район,
   отдельные параметры ГСН и ГСВ. Использовать существующую логику ГСН и
   новый модуль ГСВ без дублирования формул. Ответ содержит детализацию обоих
   разделов и суммы их подытогов, НДС и итогов. Оба раздела валидируются;
   не выдавать частичный результат за полный при ошибке одного раздела.
6. Сохранить текущий стек и локальный запуск, без новой БД и frontend framework.

## Отдельное Windows-приложение и установщик

Для установленной версии сохранить FastAPI как локальный HTTP backend,
упаковать Python-приложение вместе с зависимостями в Windows executable через
PyInstaller и показывать интерфейс в отдельном окне через pywebview. Упаковать
приложение в Windows installer через Inno Setup. Пользователю не требуется
ставить Python, открывать терминал или вручную запускать сервер. Приложение
слушает только localhost; внешний сетевой доступ не включать. Ярлык
устанавливается в Start Menu и, при выборе в установщике, на Desktop.

Обеспечить корректный lifecycle: безопасно обрабатывать занятый localhost port,
дождаться готовности backend перед показом окна, закрывать backend при закрытии
приложения и не оставлять дочерний серверный процесс. Показывать понятную ошибку
при отказе запуска. Не писать пользовательские данные в каталог установки.
Автообновление, телеметрия, облачный сервис, подписание кода и публикация
installer asset этим этапом не предполагаются.

Проверить clean Windows build и install/uninstall на Windows x64; приложение
не должно требовать Python или консоли, все три режима должны рассчитывать.
Текущий запуск через uvicorn продолжает работать для разработчика.

## Ребрендинг и компактный интерфейс

Визуальная основа — показанный пользователю вариант 1: оставить тёмно-синюю
шапку, газовую линию и бирюзовые акценты; добавить только круглый знак логотипа
ООО «Северное сияние» в его фирменном фиолетовом цвете на светлом диске.
Не использовать длинную текстовую часть фирменного логотипа. Заголовок приложения
и ярлыка — «СС.Расчет»; подпись окна «Калькулятор ГСН и ГСВ».

Сделать desktop окно компактнее, ориентир 1050×740, минимум 860×620; компоненты
перестраиваются при уменьшении и не обрезают действия/итоги. Функциональные
поля и суммы всех трёх режимов не меняются. Русифицировать Inno Setup: страницы,
кнопки, опциональная задача ярлыка рабочего стола, ошибки и удаление. Добавить
короткую стартовую заставку на русском с ненавязчивой анимацией потока газа по
трубе к дому; показывать только пока backend запускается и убрать после
readiness. Длительность не фиксирована искусственно. Заставка локальная,
не использует сеть; учитывать reduced motion.

Изображение-макет — только референс композиции, не продуктовый asset. Знак
использовать из исходного изображения логотипа сайта компании; проверить права
внутри компании/корпоративное применение. Сборка и установка остаются локальными;
не менять прайсы/API, не публиковать установщик без отдельного разрешения.

Acceptance: компактный responsive desktop window; title/shortcut `СС.Расчет`;
круглая оригинальная эмблема; RU-only installer flow; локальная splash запуска
без мерцания/ошибок и с уважением к reduced motion; все три режима и ставки
сохранены; developer uvicorn и lifecycle прежнего launcher работают; installer
переустанавливается и удаляется с сохранением пользовательских файлов.

## Уточнение компактности от 2026-11-12

Пользователь сравнил результат с выбранным макетом и запросил уменьшить
интерфейс примерно вдвое. Это уточнение заменяет прежний ориентир 1050×740:
целевое внешнее окно около 800×540, минимальное около 760×520. Размеры можно
уточнить по реальному native client area/DPI, не увеличивая окно ради сохранения
прежней длинной формы. Системный масштаб и zoom не менять.

Уточнение пользователя от 2026-11-12: основной образец композиции окна и
заставки — `docs/design/original-window-splash-reference.png` («Надо же вот
эту. Она же нам понравилась»). Воспроизвести его компоновку: тёмная шапка с
трубой/вентилем и режимами, строка заказчика, слева пары полей и отдельный
блок опций, справа результат с тёплой светлой карточкой суммы и кнопкой, снизу
труба к дому; заставка на макете — самостоятельное стартовое окно. Название
`СС.Расчет`, согласованная круглая эмблема, НДС 5%, все настоящие поля и
расчёты сохранить; старое имя, 20% и вымышленные числа не переносить.
`docs/design/approved-variant-1-reference.png` — вспомогательный образец только
фирменной эмблемы/названия, не основной макет.

Перестроить композицию: компактная шапка с эмблемой и трубой с вентилем,
переключатель режимов наверху, строка заказчика, числовые поля парами в строке,
отдельный компактный блок опций, результат справа. Отступы между строками и
блоками сократить примерно вдвое; ориентир высоты полей 28–32 px, текста
13–14 px, внутренних отступов карточек 10–12 px. Уменьшать прежде всего пустое
пространство. Кнопка расчёта и итог доступны без прокрутки всей страницы в
каждом desktop-режиме; полная детализация может раскрываться или прокручиваться
в собственной области с постоянно видимым итогом. Все поля сохраняются;
в общей смете разделы организовать компактно, не прятать обязательный ввод.

Проверять выбранный макет и настоящую собранную программу рядом, а не только
наличие цветов/эмблемы. Evidence: исходное и новое окно с размерами,
viewport и видимость действия/итога при scrollY=0, все три режима до/после
расчёта, минимум окна и мобильная ширина. Не считать прокрутку к кнопке,
screenshot workaround или обрезание доказательством видимости в исходном
viewport. Пересобрать локальный installer, сохранив предыдущий артефакт;
не закрывать текущую пользовательскую сессию без необходимости.

## Проверки и границы

Сохранить 57 существующих тестов. Добавить проверку утверждённых примеров ГСВ,
границ тарифов, исключений, неправильных значений и API-контракта.
Проверить все три режима в браузере, ошибки, переключение и мобильную ширину.
Обязательно проверить диаметры 25/26/40/41/57/58, длины 5/6, отверстия
0/1/2/3, количество комплектов САКЗ 0/1/2, ПК с САКЗ и без него,
отрицательное/дробное количество комплектов и район в общей смете.
В интерфейсе при нуле комплектов САКЗ ПК недоступен и сброшен; сервер
отклоняет сочетание ПК=true с нулём комплектов, включая общую смету.
Полный unittest suite выполняет исполнитель на интегрированном состоянии;
ревьюер оценивает реальные diff и evidence без повторения доказанных команд.

Предложение Git-политики: отдельная ветка `feature/gsv`, локальные scoped commits
после PASS. Ветка пока не создана; политика утверждается вместе с планом.
Push, merge и deployment в разрешение на реализацию не входят.

## Дополнение 2026-11-12 — смешанные диаметры

Архитектура остаётся FastAPI + локальный desktop/web frontend. Новый контракт
`pipe_lengths` содержит up_to_25/from_32_to_40/diameter_57; сервер рассчитывает
общую длину и единственную льготу5 м в порядке возрастания тарифа. Один модуль
используется отдельно и в общей смете. Старый length/diameter API остаётся
совместимым, смешение форм отклоняется. Новый ответ содержит детализацию
включённых и оплачиваемых метров. Frontend показывает три позиции длины и
реальную сумму метража. Graphics локальные по двум новым референсам; native
компактность и lifecycle сохраняются. Конкретные поля/правила/эталоны —
[план](docs/workflow/GSV-MIXED-DIAMETERS-PLAN.md). Новый installer1.1.0 локально,
release1.0.0 не менять.
