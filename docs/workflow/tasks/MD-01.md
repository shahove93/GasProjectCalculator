## Input contract

Новый mixed-ввод:

```json
"pipe_lengths": {"up_to_25": 4, "from_32_to_40": 0, "diameter_57": 4}
```

- Ровно три обязательных ключа `up_to_25`, `from_32_to_40`, `diameter_57`.
- Каждое значение — строгий integer ≥ 0 (`bool`, `float`, строка, `null`,
  отрицательное — 422).
- Лишние/неизвестные ключи внутри `pipe_lengths` и неизвестные top-level
  ключи запроса — 422.
- Legacy-форма: одновременно `length` (int ≥ 0) и `diameter` (int 1..57),
  без `pipe_lengths`; смысл и интервалы прежние.
- Смешение `pipe_lengths` с `length`/`diameter`, неполная legacy-пара
  (только один из двух), отсутствие обеих форм — 422.
- Правила одинаковы для `/calculate/gsv` и `/calculate/combined` (`gsv`).
- Серверный метраж и деньги вычисляются только сервером; клиентское поле
  `total`/`total_length` сервер не принимает и не доверяет ему.

## Formula (подтверждена пользователем)

Ставки за оплачиваемый метр: `up_to_25` 2 500; `from_32_to_40` 3 500;
`diameter_57` 4 000. База 5 м применяется один раз на раздел ГСВ.
Остаток базовых метров расходуется строго по возрастанию тарифа:
`up_to_25 → from_32_to_40 → diameter_57`.

```
remaining = 5
included(category) = min(length(category), remaining)
remaining -= included(category)
billable = length - included
surcharge(category) = billable * rate
total_length = sum(length)
length_surcharge = sum(surcharge)
```

Если сумма ≤ 5, доплата 0. Нулевые длины всех позиций сохраняют базовую
стоимость, а не бесплатный раздел. Остальные поля (база, бурение, САКЗ, ПК,
район, НДС 5%, итог) считаются как прежде.

## Response contract

Legacy-ответ (`length`+`diameter`) сохраняет ровно прежнюю форму без новых
ключей: `base_price`, `length_surcharge`, `drilling_cost`, `sakz_cost`,
`panel_cost`, `area_surcharge`, `subtotal`, `vat`, `total`.

Mixed-ответ (standalone и `combined.gsv`) дополнительно содержит:

- `total_length`: integer, сумма трёх длин;
- `pipe_breakdown`: ровно три элемента в порядке `up_to_25`,
  `from_32_to_40`, `diameter_57`, включая нулевые позиции, каждый:
  `category`, `length`, `included_length`, `billable_length`, `rate`,
  `surcharge` (все integer; `category` — одно из трёх значений выше);
- `length_surcharge` равен сумме `surcharge` элементов разбивки.

Остальные денежные поля сохраняют прежние имена и смысл. В combined
`subtotal/vat/total` верхнего уровня по-прежнему равны сумме разделов.
